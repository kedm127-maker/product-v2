# 台股產業相對估值排名

同產業內比較本益比與股價淨值比對中位數的偏離，找出相對便宜的標的，並用營收成長標記「便宜有理由」的價值陷阱。

純前端靜態頁，資料來自證交所 OpenAPI（免金鑰、免申請）。

---

## 安裝

1. 建一個 repo，把四個檔案放進去：

```
your-repo/
├── index.html
├── archive.py
├── README.md
└── .github/
    └── workflows/
        └── daily-archive.yml     ← daily-archive.yml 放這個路徑
```

2. Settings → Pages → Source 選 `Deploy from a branch`，分支選 `main`、資料夾 `/ (root)`。

3. Actions 頁籤 → `daily-archive` → `Run workflow` 手動跑一次。這一步會建立 `data/latest.json`，也是前端的備援來源。

之後每個交易日台北時間 16:10 自動跑。`data/YYYY-MM-DD.json` 會逐日累積，那是未來算「本益比自身歷史分位」的唯一來源——**沒跑到的那天補不回來**。

---

## 資料源

| 端點 | 內容 |
|---|---|
| `/v1/exchangeReport/BWIBBU_ALL` | 全上市個股本益比、股價淨值比、殖利率（當日） |
| `/v1/exchangeReport/STOCK_DAY_ALL` | 全上市個股日成交（開高低收、漲跌） |
| `/v1/opendata/t187ap05_L` | 每月營收彙總，**含官方產業別欄位**（中文名稱） |

三支用 `公司代號` / `Code` 內部連接。ETF、存託憑證因為不在月營收表裡，會自動被排除。

金額單位為新台幣千元，數值以字串回傳。`資料年月` 是民國年（`11508` = 2026 年 8 月）。

---

## 計算方式

**偏離中位數**
```
dev = mean( PE / median(產業 PE) − 1 ,  PB / median(產業 PB) − 1 )
```
兩者取平均是為了避免單一指標失真：虧損股沒有本益比，只用股價淨值比；本益比極端值也不會單獨主導。負值代表相對同業便宜。

**標記規則**
- `dev ≤ −15%` 且 營收年增 ≥ 產業中位數 → 折價候選（綠底）
- `dev ≤ −15%` 且 營收年增 < 產業中位數 → 便宜有理由（琥珀底）

第二條是這個工具存在的主要理由。同產業裡最便宜的那檔，最便宜通常有原因；沒有這條規則，排序會系統性地把你帶去族群裡最差的標的。

**同業數量門檻** 少於 5 檔的產業中位數不穩定，標題會標示，但仍然顯示。

## 這一版刻意不做的事

- **不算公允價。** 這是相對排名，不是絕對估值。跨產業比較（金融股 vs 半導體）在這個架構下無效，因為兩邊的合理倍數基準完全不同。
- **不用 DCF、EPV。** 需要現金流量表與淨負債，不在這三支端點裡。
- **不算歷史分位。** 需要至少一年的每日快照。`archive.py` 從今天開始累積，一年後才有意義。
- **不含上櫃。** TPEx 是另一套 API，欄位命名不同。

## 已知限制

品質欄位目前只有營收年增與累計年增。**營益率和 ROE 不在這三支端點裡**，要另外接綜合損益表（`/opendata/t187ap06_L_ci` 一般業、金融保險業另有端點），欄位需自行驗證。這是最值得補的下一項——營收成長是很弱的品質代理，一次性認列就會騙過它。

證交所的本益比是以近四季 EPS 計算，會包含一次性業外損益。獲利剛出現大額業外的公司，本益比會被壓低，在這張表上看起來偏便宜。

資料為證交所公開資訊，僅供研究，不構成投資建議。
